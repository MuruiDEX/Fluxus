# FLUXUS — AI Business Platform

## Стратегический план развития продукта

**Концепция:** AI Business OS + Autonomous AI Workforce + AI Marketplace.

**Цель:** единая платформа, в которой предприниматель, команда или отдельный
специалист организуют практически всю цифровую работу бизнеса с помощью ИИ.

Fluxus — не чат-бот с агентами, а рабочая среда, которая анализирует бизнес,
взаимодействует с приложениями, создаёт материалы, находит проблемы и
самостоятельно выполняет разрешённые задачи.

> реализовано — см. раздел [«Соответствие текущему коду»](#соответствие-текущему-коду)

## 1. Общая архитектура продукта

Fluxus состоит из семи основных систем:

| # | Система | Роль |
|---|---|---|
| 1 | **AI Office** | управление командой ИИ |
| 2 | **AI Workspace** | взаимодействие с программами и файлами |
| 3 | **AI Intelligence** | анализ рынка, бизнеса и данных |
| 4 | **AI Dots** | постоянные персональные агенты |
| 5 | **AI Provider Hub** | система моделей и провайдеров |
| 6 | **Marketplace** | маркетплейс агентов, инструментов и интеграций |
| 7 | **Subscription & Economy** | подписки, лимиты, платежи и экономика платформы |

Все системы работают через единый интерфейс, единую систему разрешений и
оркестратор Fluxus.

## 2. AI Office — цифровая команда сотрудников

Центральная часть Fluxus. Пользователь формулирует цель, **Team Lead**
анализирует её и распределяет работу между агентами.

### Роли агентов

| Роль | Ответственность |
|---|---|
| **Team Lead** | принимает цель, составляет план, распределяет задачи, контролирует выполнение |
| **Research Agent** | ищет информацию, изучает источники, собирает данные |
| **Business Analyst** | анализирует бизнес, показатели и эффективность |
| **Market Analyst** | исследует конкурентов, ниши и рыночные тенденции |
| **Developer** | пишет и анализирует код |
| **Designer** | работает с визуальными материалами и дизайн-системами |
| **Content Creator** | создаёт тексты, презентации, видео-концепции и материалы |
| **Finance Analyst** | анализирует финансовые показатели и бюджеты |
| **QA Agent** | проверяет результаты и ищет ошибки |
| **Personal Assistant** | помогает с повседневными задачами |

### Принцип работы

```text
User Goal → Team Lead → Planning → Parallel Agents → Review
          → Human Approval → Execution → Report → Brain
```

Пользователь видит:

- кто из агентов работает;
- какие задачи выполняются;
- какие инструменты используются;
- какие проблемы обнаружены;
- сколько ресурсов потрачено;
- какие решения требуют подтверждения.

**Требование к качеству:** агенты должны иметь реальные специализации и
инструменты, а не просто разные имена для одинаковых LLM-запросов.

## 3. AI Workspace — взаимодействие с программами

ИИ не ограничивается генерацией инструкций: он выполняет разрешённые действия
в программах.

### 3.1. Графические редакторы

Интеграции: Adobe Photoshop, Adobe Illustrator, Figma, Krita, GIMP.

Задачи: создать макет рекламного баннера; изменить размеры изображения;
подготовить несколько вариантов дизайна; организовать слои; проверить
соответствие брендбуку; экспортировать материалы в нужных форматах.

### 3.2. Видеомонтаж

Интеграции: DaVinci Resolve, Adobe Premiere Pro, Blender Video Sequencer,
другие редакторы с доступными интерфейсами автоматизации.

Возможности: анализ исходного материала; черновой монтаж; организация
видеодорожек; подготовка субтитров; поиск подходящих фрагментов; структура
ролика; проверка звука и изображения; экспорт готового проекта.

### 3.3. 3D и CAD

Интеграции: Blender, FreeCAD, Autodesk-приложения при наличии доступных API,
другие 3D/CAD-инструменты.

Возможности: создание и изменение 3D-сцен; генерация объектов через скрипты;
материалы и освещение; анализ геометрии; поиск ошибок сцены; подготовка
рендеров; создание технических моделей.

### 3.4. Офисные приложения

Microsoft Office, LibreOffice, Google Workspace, Notion и другие рабочие
приложения.

Возможности: создание документов; редактирование таблиц; подготовка
презентаций; анализ данных; автоматизация повторяющихся процессов.

### 3.5. Fluxus Desktop Bridge

```text
Fluxus Cloud / Backend → Permission Manager → Desktop Bridge
                       → Application Adapter → Target Application
```

Desktop Bridge — локальный компонент на компьютере пользователя. Отвечает за:

- обнаружение доступных приложений;
- запуск разрешённых программ;
- передачу команд;
- получение результатов;
- управление файлами в разрешённых папках;
- взаимодействие через официальные API, скрипты и UI automation.

Приоритет способов интеграции:

1. Официальный API приложения.
2. Скриптовый интерфейс приложения.
3. Локальный протокол или расширение.
4. Computer Use / UI automation — резервный вариант.

Каждое действие проходит проверку разрешений. Пользователь видит, что именно
ИИ собирается сделать, и подтверждает потенциально опасные или необратимые
операции.

## 4. AI Intelligence — интеллектуальная аналитика бизнеса

Fluxus не только исполняет задачи, но и помогает понять состояние бизнеса.

### 4.1. Market Intelligence

Исследует: размер и структуру рынка; конкурентов; новые компании; продукты и
услуги; цены; отзывы клиентов; изменения спроса; новые технологии; рыночные
возможности; потенциальные угрозы.

Результат — **Market Report** с источниками, датами, выводами и уровнем
достоверности.

### 4.2. Business Intelligence

Анализирует внутренние данные: продажи; расходы; прибыль; эффективность
сотрудников; маркетинг; конверсию; производительность; состояние проектов.
Подключение источников через API и интеграции.

### 4.3. Opportunity Detection

Ищет возможности: где бизнес теряет деньги; какие процессы можно
автоматизировать; какие продукты стоит развивать; какие сегменты клиентов
недооценены; где проблемы с эффективностью.

### 4.4. Competitor Monitoring

Пользователь выбирает конкурентов, система отслеживает доступную публичную
информацию: изменения сайтов; новые продукты; публичные цены; рекламные
кампании; новости; публичные отзывы. ИИ формирует отчёт об изменениях и
объясняет, почему они важны.

### 4.5. Error Detection

Отдельная система поиска ошибок в работе бизнеса: сломанные интеграции;
неудачные автоматизации; ошибки в данных; проблемы проектов; повторяющиеся
расходы; аномалии показателей; ошибки в документах и процессах.

Каждая проблема получает приоритет, описание, доказательства и предложение
решения. **Никаких автоматических изменений без разрешений.**

## 5. AI Dots — постоянные персональные агенты

Dot — не обычный чат, а отдельный агент с целью, памятью, разрешениями и
набором инструментов.

| Dot | Что делает |
|---|---|
| **Business Dot** | следит за показателями, выявляет отклонения, сообщает о проблемах, готовит ежедневные отчёты |
| **Market Dot** | отслеживает рынок, анализирует конкурентов, собирает новости, находит возможности |
| **Development Dot** | наблюдает за проектами разработки, анализирует ошибки, следит за тестами, предлагает исправления |
| **Marketing Dot** | анализирует рекламные результаты, отслеживает контент, предлагает улучшения |
| **Personal Dot** | управляет задачами, помогает планировать, напоминает о событиях |

Каждый Dot имеет: собственную память; цели; расписание; инструменты;
разрешения; бюджет; журнал действий; систему уведомлений. Пользователь может
создать собственного Dot через конструктор.

**Важное отличие:** Dots работают по событиям, расписанию и разрешённым
условиям, а не постоянно отправляют запросы к LLM — это снижает расходы и
убирает ненужную активность.

## 6. AI Provider Hub — динамическая система ИИ-моделей

Ключевая часть экономики Fluxus: работа бесплатно на доступных бесплатных
моделях, подключение платных — по необходимости.

### 6.1. Единый каталог провайдеров

Каталог всех поддерживаемых моделей. Семейства: OpenAI, Anthropic, Google,
DeepSeek, Qwen, Mistral, Zhipu, MiniMax, другие открытые и коммерческие
модели. Подключение новых моделей — максимально простое.

### 6.2. Динамическое обнаружение моделей

Каталог регулярно обновляется через поддерживаемые API, официальные каталоги
и проверенные источники. Для каждой модели хранится: название; провайдер;
идентификатор; поддерживаемые возможности; контекстное окно; доступные режимы;
стоимость; статус доступности; ограничения; дата последней проверки.

### 6.3. Free Model Discovery

Статусы модели: **Free**, **Free with Limits**, **Trial**, **Paid**,
**Unavailable**, **Deprecated**.

Если провайдер прекращает бесплатный доступ:

1. Система обнаруживает изменение.
2. Повторно проверяет доступность.
3. Переводит модель в Paid или Unavailable.
4. Убирает её из категории бесплатных.
5. Сохраняет информацию о модели в каталоге.
6. Предлагает бесплатную альтернативу.

Модель **не удаляется** из истории пользователей и конфигураций. Если модель
временно недоступна, задачи не переключаются на платную модель без согласия
пользователя.

### 6.4. Model Router

| Задача | Предпочтительный тип модели |
|---|---|
| Простая классификация | быстрая бесплатная модель |
| Исследование | модель с сильным reasoning |
| Программирование | coding-модель |
| Изображения | vision-модель |
| Работа с документами | большое контекстное окно |
| Сложная аналитика | сильная reasoning-модель |

Учитывать: качество, стоимость, скорость, доступность, ограничения,
конфиденциальность.

Режимы выбора: **Auto**, **Free Only**, **Best Quality**, **Lowest Cost**,
**Custom**.

### 6.5. Подключение пользовательских провайдеров

OpenAI-compatible API; локальные модели; Ollama; другие поддерживаемые
протоколы. Пользователь добавляет собственные API-ключи. Ключи хранятся
безопасно, отдельно от обычных данных, и никогда не передаются другим
пользователям или маркетплейсу.

### 6.6. Локальные модели

Использование вычислительных ресурсов компьютера пользователя: Ollama,
llama.cpp, другие локальные inference-системы — работа без оплаты облачного
API, если оборудование позволяет запуск выбранной модели.

## 9. Fluxus Credits — система расходов

Вместо абстрактного количества сообщений — прозрачный расход ресурсов.

У каждой задачи отображается: использованная модель; стоимость API;
вычислительные расходы; стоимость инструментов; общий расход; источник оплаты.

Источники оплаты: бесплатная квота Fluxus; подписка; пользовательский
API-ключ; локальная модель; платный инструмент Marketplace.

Перед дорогими операциями пользователь получает оценку расходов.
Обязательные ограничения:

- лимит расходов;
- максимальная стоимость задачи;
- остановка при исчерпании бюджета;
- подтверждение платного fallback;
- история расходов.

Стоимость подписки **не смешивается** с фактической себестоимостью
AI-запросов.

## 10. Unified Permission System

Категории: **Read** (чтение данных); **Write** (изменение данных);
**Execute** (выполнение действий); **External Communication** (сообщения и
публикация); **Financial** (платные операции); **Administrative** (аккаунты и
настройки).

Разрешения задаются отдельно для: агентов; Dots; приложений; плагинов;
бизнесов; рабочих пространств.

Примеры: прочитать документ — разрешено; изменить документ — по разрешению;
отправить сообщение клиенту — подтверждение; опубликовать рекламную кампанию —
подтверждение; оплатить сервис — подтверждение.

Каждое действие записывается в **Audit Log**.

## 11. Архитектура технической платформы

Не строить всё как один огромный backend-модуль.

**Frontend:** AI Office; Workspace; Intelligence; Dots; Marketplace; Billing;
Settings.

**Backend:** Identity & Organization; AI Orchestrator; Agent Runtime; Provider
Registry; Model Router; Tool Registry; Permission Manager; Workflow Engine;
Memory Service; Market Intelligence; Marketplace Service; Billing & Usage;
Notification Service.

**Desktop:** Fluxus Desktop Bridge; Application Adapters; Local Model
Connector; File Access Layer; Computer Use.

**Infrastructure:** PostgreSQL; Redis / очереди задач; Object Storage; Worker
Runtime; Event System; Monitoring.

Это **целевая** архитектура. На первых этапах — модульный backend; сервисы
выделяются только при реальной необходимости.

## 13. Главные принципы Fluxus

1. **Model Agnostic** — пользователь не привязан к одному провайдеру.
2. **Free First** — бесплатные модели доступны без подписки, в пределах их
   реальных лимитов.
3. **Extensible** — возможности расширяются через Marketplace.
4. **Action Oriented** — ИИ не только отвечает, но и выполняет задачи.
5. **Human Control** — пользователь контролирует важные действия.
6. **Persistent Intelligence** — Dots работают с долговременным контекстом.
7. **Transparent Economy** — все расходы понятны.
8. **Open Ecosystem** — сторонние разработчики создают расширения.
9. **Security by Design** — доступ к данным и приложениям регулируется
   разрешениями.
10. **Modular Architecture** — новые возможности не разрушают систему.

## 14. Итоговое видение

Fluxus объединяет: ChatGPT (интеллектуальный интерфейс), OpenCode (работа с
разными моделями и инструментами), Dots (постоянные агенты), Zapier / n8n
(автоматизация), Photoshop / Blender / DaVinci (создание контента),
бизнес-аналитику (понимание рынка) и Marketplace (расширяемая экосистема).

Но Fluxus не копирует эти продукты. Главное преимущество — единая среда, в
которой пользователь формулирует бизнес-цель, получает команду ИИ, подключает
нужные инструменты, контролирует выполнение и видит результат.

**Конечная цель: пользователь управляет работой, а Fluxus предоставляет
цифровую инфраструктуру для её выполнения.**

### Чего ещё нет (ни в коде, ни в схеме БД)

- **Model Router / каталог моделей / Free Model Discovery / статусы
  Free→Paid** (§6.1–6.4): провайдер выбирается настройкой окружения, одна
  модель на инсталляцию; каталога моделей, проверки доступности и
  автоматического переключения нет.
- **Подписки и тарифы Free/Plus/Pro/Business/Enterprise** (§8): нет планов,
  квот по тарифу, биллинга, платежей. Лимиты сейчас — бюджеты проекта/бизнеса.
- **Квоты Fluxus Credits** (§9): ledger и стоимости есть, «бесплатной квоты»,
  квоты подписки и выбора источника оплаты нет.
- **AI Dots** (§5): нет сущностей Dot, расписаний, событийного триггера,
  уведомлений, конструктора.
- **AI Intelligence** (§4): нет Market/Business Intelligence, мониторинга
  конкурентов, Error/Opportunity Detection — есть только агенты-роли,
  исполняющие задачи в рамках проекта.
- **Unified Permission System и Audit Log** (§10): есть approval-гейты и
  метаданные разрешений у листингов маркетплейса, но нет Permission Manager
  с категориями Read/Write/Execute/External/Financial/Administrative и
  сквозного аудита действий.
- **Fluxus Desktop Bridge** (§3.5): нет локального компонента, адаптеров
  приложений, file access layer, Computer Use; Tauri-упаковка отложена.
- **Marketplace-монетизация и SDK** (§7.3, Phase 8): нет публикации сторонних
  расширений, комиссии, Developer Dashboard, публичного API/SDK.

### Ближайшие шаги (по плану, с учётом текущего кода)

1. **Phase 2 — Provider Hub:** реестр моделей (provider, model, capabilities,
   context, cost, status, `last_checked`), нормализация провайдеров поверх
   существующего `app/llm`, Model Router с режимами Auto / Free Only / Best
   Quality / Lowest Cost / Custom. Бесплатные модели — реальная основа
   тарифа Free.
2. **Phase 3 — Credits & Subscription:** квоты поверх готового
   `app/usage` ledger (`usage_status`, `cost`, тарифы уже есть), планы и
   лимиты, запрет платного fallback без согласия.
3. **Phase 4 — AI Intelligence:** отчёты с источниками и достоверностью,
   Error Detection на существующих данных (`activity log`, usage ledger,
   проекты/задачи).
4. **Phase 5 — AI Dots:** сущность Dot (цель, память, расписание, бюджет,
   разрешения), событийный запуск, а не постоянные LLM-запросы.
5. **Phase 6 — Marketplace:** расширить декларативные пакеты до публикации,
   модерации и монетизации; Designer/Developer Dashboard.
6. **Phase 7 — Desktop Bridge:** локальный агент + Permission Manager +
   адаптеры (Blender, офис, видеоредакторы) + локальные модели.
